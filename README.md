# gatherup

GatherUp 整组候补与临时占位模块：纯 Go 库，数据保存在进程内存，无外部依赖。
每个 `Activity` 实例管理一个容量固定的活动，提供报名、确认、取消、查看状态四类能力。

## 规则摘要

- 报名按整组人数申请席位，整组不可拆分；仅「待确认」和「已确认」占用席位。
- 每次分配时，从人数不超过剩余席位的候补中选最早报名者，整组转为待确认，
  重复直到没有候补能放下；暂时放不下的大组保留原顺序，不挡住后面能放下的小组。
- 待确认占位从实际获席时起持续 900 秒；确认后不再过期；取消释放全部席位或退出候补。
- 所有操作携带调用方给定的非递减整数秒时间。某时刻全部到期报名先一起释放席位再递补，
  之后才处理该时刻的外部操作，因此恰在截止时刻确认不能成功。
- 没有调用的时间段仍视为正常发生到期与递补：后来调用跨过多个截止时刻时，
  每轮递补的获席时间是当时释放席位的时刻，空档中新获席者也可能再次到期。
  因此连续查看与隔很久查看得到相同结果。

## 调用示例

```go
a, _ := gatherup.NewActivity(3) // 容量 3 的活动

id1, _ := a.Register(0, 2)  // 时刻 0，2 人组报名 -> 待确认，占 2 席
id2, _ := a.Register(0, 3)  // 3 人组 -> 候补（剩余席位不足）
id3, _ := a.Register(0, 1)  // 1 人组 -> 待确认，占最后 1 席

_ = a.Confirm(100, id1)     // 确认 id1，不再自动过期
_ = a.Cancel(200, id3)      // 取消 id3，释放 1 席（不足 id2 的 3 人，仍候补）

v := a.Status(900)          // 推进到时刻 900 并查看快照
// v.Remaining      剩余席位
// v.Registrations  每笔报名的 ID/人数/状态/获席时间 GrantedAt/取消时间 CancelledAt
//                  （未获席、未取消时对应字段为 -1）
```

## API

- `NewActivity(capacity int) (*Activity, error)`：创建活动实例。
- `Register(now, size int64/int) (int, error)`：整组报名，返回报名 ID。
- `Confirm(now int64, id int) error`：确认待确认报名。
- `Cancel(now int64, id int) error`：取消报名，释放席位或退出候补。
- `Status(now int64) View`：查看快照（剩余席位 + 每笔报名状态/获席时间/取消时间）。

占位时长为常量 `HoldSeconds = 900` 秒。`Activity` 不是并发安全的，
多 goroutine 调用请自行加锁。

## 测试

```sh
go test ./...
```

覆盖：同刻到期释放 3 席时最早的 3 人候补整组获席（不分给较晚的 2 人候补）；
一次跳过 1 小时与逐秒查看结果一致、跨过空档的每轮占位只持续 900 秒、
截止时刻确认不能复活报名；以及基本报名/确认/取消/递补流程与错误处理。
