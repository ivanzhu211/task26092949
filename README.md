# gatherup

社区活动整组报名、候补与临时占位库。纯进程内存实现，每个 `Activity` 实例管理一个活动，由上层直接调用。

## 规则摘要

- 容量固定，每笔报名按整组人数申请席位，整组不可拆分。
- 状态：候补（waitlisted）、待确认（pending）、已确认（confirmed）、已取消（cancelled）；仅待确认与已确认占用席位。
- 递补时反复选择人数不超过剩余席位的最早候补，整组转为待确认；放不下的大组保留原顺序，可被能放下的小组跳过，但任何报名都不能抢在能放下的老候补之前。
- 待确认占位从实际获席时刻起持续 900 秒（`PendingTTL`）。确认后不再过期；到期未确认直接取消，不重新入队。
- 所有操作携带调用方给定的非递减整数秒时间。某时刻的全部到期先一起释放席位并完成递补，之后才处理该时刻的外部操作，因此恰在截止时刻确认会失败。
- 没有调用的空档仍按真实时间线发生到期与递补：跨过多个截止时刻时，每轮递补的获席时间是当时释放席位的时刻，空档中新获席者也可能再次到期。连续查看与隔很久查看结果一致。

## API

```go
a := gatherup.NewActivity(4) // 容量 4；容量非正会 panic

id, err := a.Register(now, 3) // 整组 3 人报名，返回编号（从 1 开始）
err = a.Confirm(now, id)      // 确认待确认报名；非待确认返回 ErrNotPending
err = a.Cancel(now, id)       // 取消：释放席位或退出候补，并触发本次递补
v := a.View(now)              // 快照：Remaining 剩余席位 + 每笔报名状态
```

`View.Registrations` 中每笔报名包含：

- `ID` / `Size`：编号与整组人数
- `Status`：`StatusWaitlisted` / `StatusPending` / `StatusConfirmed` / `StatusCancelled`
- `GrantedAt`：获席（转为待确认）时刻，未获席为 -1
- `CancelledAt`：取消生效时刻，未取消为 -1

`now` 必须非递减（传入更早的时刻会被钳制到已见的最大时刻）。实例非并发安全。

## 运行测试

```sh
go test ./...
```

测试覆盖：同刻到期释放 3 席时最早的 3 人候补整组获席（较晚的 2 人候补不插队）；一次跳过 1 小时与逐秒查看结果一致；每轮占位只持续 900 秒；截止时刻确认不能复活报名；基本流程、顺序保持与非法输入。
